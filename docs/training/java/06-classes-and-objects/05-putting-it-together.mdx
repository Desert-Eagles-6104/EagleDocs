בחלק הזה נבנה תוכנית קטנה שמשלבת מחלקות, אובייקטים, שדות, מתודות, בנאים והרשאות.

**המטרה היא לכתוב ולהסביר תוכנית משלכם.** קראו קודם את הדרישות ותכננו; אל תתחילו מהעתקת הפתרון.

:::info מודל לימודי
המחלקות כאן שומרות ערכים בתוכנה. הן לא מפעילות מנועים פיזיים ולא מחליפות את `Robot` של WPILib. בהמשך נחבר את עקרונות הארגון האלה לקוד FRC אמיתי.
:::

## 1. מה אנחנו בונים?

עד עכשיו `Robot` שמר את המהירות בעצמו. עכשיו ניתן את האחריות הזאת ל־`Motor`, ונאפשר ל־`Robot` להשתמש במנוע.

| מחלקה | מה היא שומרת? | על מה היא אחראית? |
| --- | --- | --- |
| `Motor` | פקודת מהירות | שינוי בטווח מותר, עצירה והחזרת המהירות |
| `Robot` | שם ומנוע | הפעלת המנוע והצגת מצב הרובוט |
| `Main` | משתנים מקומיים במהלך ההרצה | יצירת האובייקטים ובדיקת התנהגותם |

לא ניצור ב־`Robot` שדה `double speed` נוסף: המידע הזה יהיה במנוע. כך לא יהיו שני ערכים שצריך לזכור לעדכן יחד.

:::info ממשיכים באותו פרויקט Java
השאירו את `src/Robot.java` ואת שאר התרגילים במקומם. בתוך `src` צרו תיקייה בשם `mechanisms`. כאן נכתוב `Main.java`, `Motor.java` ו־`Robot.java` חדשים, בלי לשנות את הגרסאות הקודמות.

בשורה הראשונה של **כל אחד משלושת הקבצים** כתבו `package mechanisms;`. חבילה (package) נותנת לקבוצת מחלקות שם משותף: `mechanisms.Robot` ו־`Robot` מהתרגילים הקודמים הם טיפוסים שונים, ולכן יכולים להתקיים באותו פרויקט. אין צורך לייבא מחלקות שנמצאות יחד באותה חבילה.

הריצו דרך **Run שמעל main בקובץ `src/mechanisms/Main.java`**. אם מוצעת בחירת מחלקה, בחרו `mechanisms.Main`. לא יוצרים פרויקט נוסף ולא מעתיקים את התיקייה כולה.
:::

## 2. חיבור קצר: שדה יכול להיות גם מטיפוס מחלקה

כבר השתמשנו בשדות `String` ו־`double`. אפשר להגדיר גם שדה מטיפוס שיצרנו:

```java
private Motor motor;
```

ההכרזה הזאת **אינה יוצרת מנוע**. היא מגדירה שדה שבו נוכל לשמור הפניה למנוע. בפרויקט הזה `Robot` ייצור מנוע בבנאי:

```java
public Robot(String name) {
    this.name = name;
    motor = new Motor();
}
```

כל יצירה של `Robot` תפעיל את הבנאי, ובתוכו תיצור גם `Motor` חדש. אם ניצור שני רובוטים כך, לכל אחד יהיה מנוע נפרד.

מתודה של `Robot` יכולה להפעיל מתודה של המנוע:

```java
public void stop() {
    motor.stop();
}
```

כש־`Main` קורא ל־`first.stop()`, אנחנו נכנסים לפעולת `stop` של הרובוט הראשון; היא קוראת ל־`stop` של המנוע ששמור בו. לא מעתיקים את הקוד של `Motor` אל `Robot`, אלא משתמשים באובייקט שלו.

זה החיבור היחיד החדש שנצטרך כאן: **שדה מטיפוס מחלקה וקריאה למתודות של האובייקט ששמור בו.**

## 3. מתכננים לפני שכותבים

ענו על השאלות בלי לפתוח פתרון:

1. באיזו מחלקה יימצא השדה `speed`?
2. איזו מחלקה תבדוק שהמהירות בטווח?
3. איך `Robot` יבקש לעצור את המנוע בלי לגשת לשדה שלו?
4. איך `Main` יקבל את מהירות הרובוט בלי לגשת למנוע ישירות?
5. איפה נשתמש ב־`new` כדי לקבל שני רובוטים עם מנועים נפרדים?

השוו את התכנון לדרישות בשלבים הבאים. בכל שלב כתבו והריצו בדיקה קטנה לפני ההמשך.

## 4. שלב א: מחלקת Motor

צרו `Motor.java` עם:

- שדה פרטי `double speed`.
- בנאי ללא פרמטרים שמתחיל במהירות `0`.
- `public void setSpeed(double speed)` שמקבל רק ערכים בטווח `-1` עד `1`, כולל הקצוות. בקשה לא תקינה משאירה את המהירות הקודמת.
- `public double getSpeed()` שמחזיר את המהירות.
- `public void stop()` שעוצר את המנוע.

ב־`main` צרו מנוע, בקשו `0.5`, בקשו `3`, עצרו והדפיסו אחרי כל פעולה. הפלט הצפוי: `0.5`, אחריו `0.5`, ואחריו `0.0`.

<ExerciseHelp
  hints={["מי אחראי לשמור את המהירות בטווח? רכזו את הבדיקה במחלקה שמחזיקה את השדה.", "זה אותו כלל מהחלק הקודם; השינוי הוא שהאחריות נמצאת עכשיו ב־Motor.", "הבנאי מתחיל באפס. setSpeed בודק את שני הגבולות יחד; stop יכול לקרוא ל־setSpeed(0)."]}

package mechanisms;

public class Motor {
    private double speed;

    public Motor() {
        speed = 0;
    }

    public void setSpeed(double speed) {
        if (speed >= -1 && speed <= 1) {
            this.speed = speed;
        }
    }

    public double getSpeed() {
        return speed;
    }

    public void stop() {
        setSpeed(0);
    }
}

// בתוך main
Motor motor = new Motor();
motor.setSpeed(0.5);
System.out.println(motor.getSpeed()); // 0.5
motor.setSpeed(3);
System.out.println(motor.getSpeed()); // 0.5
motor.stop();
System.out.println(motor.getSpeed()); // 0.0`}

## 5. שלב ב: מחלקת Robot

צרו `Robot.java` עם:

- שדה פרטי `String name` ושדה פרטי `Motor motor`.
- בנאי `Robot(String name)` ששומר את השם ויוצר מנוע חדש.
- `public void drive(double speed)` שמבקש מהמנוע את המהירות הזאת.
- `public void stop()` שעוצר את המנוע.
- `public double getSpeed()` שמחזיר את מהירות המנוע.
- `public void printStatus()` שמדפיס את השם ואת המהירות, כל אחד בשורה נפרדת.

**אל תוסיפו שדה מהירות נוסף ואל תעתיקו את תנאי הטווח ל־Robot.** `Motor` כבר אחראי על המהירות ועל הכלל שלה.

בדקו ב־`Main`: יצירה של רובוט, `drive(0.75)`, הדפסת מצב, עצירה והדפסת מצב נוספת.

<ExerciseHelp

public class Robot {

    public void drive(double speed) {
        motor.setSpeed(speed);
    }

    public void stop() {

## 8. אתגר: שני מנועים לכל רובוט

עד עכשיו לכל רובוט היה מנוע אחד. עכשיו נשדרג אותו כך שיוכל לשלוט בשני מנועים בנפרד.

**עבדו עם אותם קבצים:** `Robot.java`, `Motor.java` ו־`Main.java`. אין צורך ליצור מחלקות חדשות או לשנות את `Motor`.

ב־`Robot`:

1. החליפו את `motor` בשני שדות פרטיים: `leftMotor` ו־`rightMotor`.
2. בבנאי צרו שני אובייקטים נפרדים של `Motor`.
3. שנו את `drive` לקבל שתי מהירויות, אחת לכל מנוע.
4. עדכנו את `stop()` לעצור את שניהם.
5. החליפו את `getSpeed()` ב־`getLeftSpeed()` ו־`getRightSpeed()`.
6. עדכנו את `printStatus()` להדפיס את שם הרובוט ואת שתי המהירויות.

עדכנו גם את `Main.java` ובדקו נסיעה, עצירה, ובקשה שבה רק אחת המהירויות אינה תקינה. זכרו שכל מנוע בודק את הבקשה שלו בנפרד.

## בדיקת סיום

**בלי להסתכל על הפתרון**, הוסיפו ל־`Robot` מתודה בשם `isMoving()` שמחזירה `true` אם לפחות אחד מהמנועים נע, ו־`false` אחרת.

בדקו את המתודה לפני נסיעה, בזמן נסיעה ואחרי עצירה.

לאחר מכן, הסבירו:
- מה קורה מרגע הקריאה ל־`first.drive(0.5, -0.25)` ועד שהמהירויות משתנות?
- למה עצירת `first` לא עוצרת גם את `second`?

<escape><ExerciseHelp
  hints={[

    "לכל Robot נוצרים שני אובייקטים נפרדים של Motor בבנאי."

    return getLeftSpeed() != 0 || getRightSpeed() != 0;
