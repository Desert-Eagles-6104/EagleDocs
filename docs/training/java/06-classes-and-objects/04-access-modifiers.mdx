## 1. קודם מגדירים את הכלל

במודל הלימודי שלנו, נגדיר ערך מהירות מותר בין `-1` ל־`1`, כולל הקצוות:

- `0` הוא עצירה.
- ערך חיובי מייצג תנועה בכיוון אחד.
- ערך שלילי מייצג תנועה בכיוון השני.

הערך אינו מהירות במטרים לשנייה. זו דרך לימודית לייצג פקודת תנועה; אנחנו עדיין לא מפעילים חומרה.

כשהשדה ציבורי, הקוד הזה מתקמפל:

```java
Robot robot = new Robot("Eagle", 0.5);
robot.speed = 500;
```

Java יודעת ש־`500` מתאים ל־`double`, אבל לא מכירה את הכלל שהמצאנו. כל מי שמשתמש במחלקה צריך לזכור בעצמו לא להכניס ערך לא מתאים.

## 2. private מגביל גישה ישירה

נשנה את השדות בתוך `Robot`:

```java
private String name;
private double speed;
```

קוד בתוך `Robot` עדיין יכול להשתמש בהם. לעומת זאת, גישה ישירה מתוך המחלקה הנפרדת `Main` תגרום לשגיאת קומפילציה:

```java
// דוגמה שגויה בתוך main
robot.speed = 0.5;
System.out.println(robot.speed);
```

`private` לא בודק אם המספר חוקי. הוא חוסם את הגישה הישירה מבחוץ, כדי שנוכל לבחור איך לאפשר קריאה ושינוי דרך פעולות מוגדרות.

## 3. public חושף דרך להשתמש באובייקט

נאפשר לקבל את המהירות בעזרת המתודה שכבר כתבנו:

```java
public double getSpeed() {
    return speed;
}
```

נוסיף דרך לשנות אותה, עם בדיקה:

```java
public void setSpeed(double speed) {
    if (speed >= -1 && speed <= 1) {
        this.speed = speed;
    }
}
```

במודל הזה **בקשה עם ערך לא תקין נדחית, והמהירות הקודמת נשארת**. זה כלל שבחרנו לתרגיל; Java לא מחליטה עליו עבורנו.

בתוך `main`:

```java
Robot robot = new Robot("Eagle", 0.5);
robot.setSpeed(0.75);
robot.setSpeed(500);
System.out.println(robot.getSpeed()); // 0.75
```

למתודות כאלה קוראים לעיתים Getter ו־Setter. לא צריך ליצור אוטומטית Getter ו־Setter לכל שדה. נחשוף רק את הפעולות הדרושות: למשל, אם לא רוצים לשנות שם אחרי היצירה, לא נוסיף `setName`.

## 4. כימוס: המחלקה אחראית על המידע שלה

**כימוס (Encapsulation)** הוא ארגון המידע והפעולות יחד, והגדרת הדרך שבה שאר התוכנית משתמשת בהם. כאן `Robot` אחראית לכלל של טווח המהירות.

אבל אין די בבדיקת `setSpeed`. אם מתודה אחרת או בנאי יעקפו אותה, הם עדיין יכולים לשמור ערך לא תקין.

נעדכן גם את הבנאי:

```java
public Robot(String name, double speed) {
    this.name = name;
    this.speed = 0;
    setSpeed(speed);
}
```

מתוך `Robot` אפשר לקרוא ל־`setSpeed(speed)` בלי לכתוב לפניו משתנה ונקודה: זו פעולה על האובייקט הנוכחי. אם המהירות ההתחלתית לא תקינה, היא תישאר אפס.

ונעדכן את `accelerate`:

```java
public void accelerate(double amount) {
    setSpeed(speed + amount);
}
```

עדכנו גם את `doubleSpeed()` מבדיקת הסיום של חלק המתודות כך שתשתמש ב־`setSpeed(speed * 2)`. אם הוספתם בנאים נוספים, ודאו שגם הם משתמשים בבדיקת הטווח. אין להשאיר דרך אחרת שעוקפת את הכלל.

עכשיו גם האצה עוברת דרך אותה בדיקה. אם הסכום חורג מהטווח, כל בקשת ההאצה נדחית; לא מגבילים את התוצאה אוטומטית לערך הקצה.

## 5. מחלקה מלאה, אחרי התיקון

עדכנו את `Robot.java` שלכם. הדוגמה מרכזת את פעולות הליבה; אם כתבתם גם `rename`, השאירו אותה. השאירו גם את `doubleSpeed` מבדיקת הסיום, עם בדיקת הטווח כפי שמופיע כאן. שמרו רק גרסה אחת של המחלקה:

```java
public class Robot {
    private String name;
    private double speed;

    public Robot(String name, double speed) {
        this.name = name;
        this.speed = 0;
        setSpeed(speed);
    }

    public void setSpeed(double speed) {
        if (speed >= -1 && speed <= 1) {
            this.speed = speed;
        }
    }

    public double getSpeed() {
        return speed;
    }

    public void accelerate(double amount) {
        setSpeed(speed + amount);
    }

    public void doubleSpeed() {
        setSpeed(speed * 2);
    }

    public void stop() {
        setSpeed(0);
    }

    public boolean isMoving() {
        return speed != 0;
    }

    public void printStatus() {
        System.out.println(name);
        System.out.println(speed);
    }
}
```

אם כתבתם בחלק הקודם בנאים נוספים, עדכנו גם אותם כך שלא ישמרו מהירות לא תקינה. בדוגמה הזאת השארנו רק את הבנאי שמקבל שם ומהירות.

### אתגר: פעולה פנימית

הוסיפו ל־`Robot` מתודה פרטית `boolean isValidSpeed(double value)` שמחזירה אם הערך בטווח. השתמשו בה בתוך `setSpeed`.

למה אין צורך שקוד ב־`Main` יוכל לקרוא לה? מה יקרה אם ינסה?

<ExerciseHelp
  hints={["אפשר לתת private גם למתודה, לא רק לשדה.", "המתודה הפרטית יכולה להחזיר את תוצאת התנאי שכבר כתבתם."]}

## לפני שממשיכים: בדקו את עצמכם

צרו מחלקה `Battery` עם שדה פרטי `int percent`. הבנאי יקבל אחוז טעינה התחלתי. הוסיפו `getPercent()` ו־`setPercent(int percent)`.

הכללים:

- רק ערכים בין `0` ל־`100` מתקבלים.
- ערך התחלתי לא תקין משאיר `0`.
- שינוי לא תקין משאיר את הערך הקודם.

בדקו ב־`Main` את ערכי הקצה `0` ו־`100`, וגם את `150`.

הסבירו: למה `private` לבדו לא מספיק? באילו מקומות במחלקה צריך לשמור על הכלל?
