**סימולציה** היא הרצה של קוד הרובוט על המחשב, עם מודל שמחשב איך הרובוט היה מגיב. לא צריך לחבר roboRIO או מנועים. נשתמש בפרויקט שכבר שוכפל, ונפעיל את מערכת הנהיגה הקיימת שלו.

**swerve** היא מערכת הנהיגה שבה כל גלגל יכול גם להסתובב סביב הציר שלו וגם לשנות את כיוון הנסיעה שלו. כרגע נבדוק נסיעה וסיבוב, בלי ללמוד איך בונים את המערכת.

:::warning לפני הניסוי
בגרסת התבנית שנבדקה חסרים ערכי הגדרה למערכת הנהיגה. המנטור צריך להשלים ולבדוק אותם לפני המפגש. אם התוכנית נכשלת מיד בהפעלה, הראו את ההודעה למנטור; זו אינה משימה לנחש הגדרות מנוע. [מידע מפורט למנטור](../template-readiness.mdx).
:::

## 1. חוזרים לפרויקט שהכנו

פתחו את המאגר האישי ב־WPILib VS Code 2026. ב־Explorer ודאו שרואים `build.gradle`, לא רק תיקיית `src`.

את הבנייה הראשונה כבר ביצענו בפרק יצירת המאגר. אם עדיין לא קיבלתם `BUILD SUCCESSFUL`, חזרו ל[בנייה הראשונה ופתרון תקלות](./02-template-repository.mdx#first-build) לפני ההרצה.

## 2. מפעילים סימולציה

1. פתחו את [חלון הפקודות](./00-working-in-vscode.mdx#command-palette).
2. חפשו `WPILib: Simulate Robot Code` ובחרו אותה. אל תלחצו על המשולש Run Java ליד `Main`: הוא אינו מכין את סביבת הסימולציה של הפרויקט.
3. אם מופיעה בחירת הרחבות, השאירו **Sim GUI** מסומנת ואת הרחבת Driver Station אם היא מופיעה, ולחצו **OK**.
4. המתינו לחלון חדש בשם **Robot Simulation** ולפלט ההרצה ב־VS Code.

אפשר ללחוץ על צילום המסך כדי לפתוח אותו בגודל מלא בלשונית חדשה. זה שימושי במיוחד כשקוראים בטלפון.

## 3. מכירים את ארבעת אזורי העבודה

**Driver Station** היא עמדת הבקרה שמוסרת לרובוט את הקלט מהשלט ואת מצב ההפעלה. בסימולציה אפשר להשתמש באזורי הבקרה שבחלון Robot Simulation; אין צורך להתחבר לרובוט פיזי.

לא צריך להבין את כל החלוניות עכשיו. אם אחת מארבע אלה חסרה, פתחו את תפריט **DS** בחלון הסימולציה ובדקו את האפשרויות להצגתה. הרחיבו חלונית סגורה באמצעות המשולש שליד הכותרת.

**Disabled** פירושו שהרובוט מושבת: התוכנית רצה, אבל אין אישור להפעיל מנועים. **Teleop / Teleoperated** הוא מצב שליטה באמצעות השלט. נתחיל ב־Disabled.

## 4. בוחרים צד ומשייכים שלט

1. באזור **Robot State** לחצו **Disabled**. אל תפעילו לפני שסיימתם לבדוק קלט.
2. באזור **FMS**, פתחו את הרשימה ליד **Alliance Station** ובחרו **Blue 1**. Alliance היא הקבוצה הכחולה או האדומה במגרש; בקוד הזה נהיגה לא תפיק מהירויות כשלא נבחר צד.
3. חברו שלט PS5 או Xbox למחשב. הוא צריך להופיע ברשימת **System Joysticks**.
4. לחצו על שורת השלט, החזיקו את כפתור העכבר וגררו אותה אל **Joystick[0]** באזור **Joysticks**. הספרה 0 חשובה: זה מספר יציאת השלט שקוד התבנית קורא.
5. הזיזו בעדינות סטיק. **ציר (Axis)** הוא ערך מספרי שמשתנה לפי מידת ההטיה של הסטיק. צפו לשינוי של ערכי הצירים בחלונית Joystick[0]. לחיצה על כפתור אמורה לשנות את חיווי הכפתור.

![גוררים שלט מרשימת System Joysticks לאחת מיציאות Joysticks; אצלנו בוחרים Joystick[0]](../assets/interfaces/sim-gui-dragging-joysticks.png)

**בדיקת עצירה לפני המשך:** אם השלט מופיע ברשימת המחשב אבל עדיין כתוב `Unassigned` מתחת ל־Joystick[0], הוא עוד לא משויך לקוד. אם אין שינוי בצירים, לא מנסים לתקן באמצעות הגדלת מהירות. בקשו מהמנטור לבדוק זיהוי ומיפוי - ההתאמה בין כפתורי השלט למספרים שהקוד קורא. התבנית מתחילה במיפוי PS5 ומנסה לזהות גם Xbox; לשלט לא מזוהה ייתכן שיידרש מיפוי אחר. אין בתבנית מיפוי מקלדת מוכן לנהיגה.

## 5. פותחים תצוגה שבה רואים את הרובוט

**AdvantageScope** היא תוכנה לצפייה בנתונים שהרובוט שולח - מספרים, גרפים ומיקום על מגרש. **NetworkTables** היא הדרך שבה תוכנית הסימולציה שולחת את הנתונים לתוכנה. אין צורך לכתוב קוד תקשורת בשביל הניסוי הזה.

1. ב־VS Code פתחו את [חלון הפקודות](./00-working-in-vscode.mdx#command-palette) ובחרו **WPILib: Start Tool**. אם מופיעה AdvantageScope ברשימת הכלים, בחרו אותה. אפשר גם לחפש AdvantageScope בתפריט ההתחלה של Windows. אם היא לא מותקנת, המנטור יתקין אותה לפי [הוראות הכלי](https://docs.advantagescope.org/overview/installation).
2. בתוך AdvantageScope בחרו **File → Connect to Simulator**. אם יש בחירת מקור, בחרו **NetworkTables (AdvantageKit)**.
3. המתינו: כשהכותרת מראה `Searching`, החיבור עוד מחפש נתונים. אחרי חיבור אמורים להופיע ענפי נתונים ברשימה שבצד שמאל. הסימולציה צריכה להמשיך לרוץ בינתיים.
4. לחצו על `+` ליד לשוניות התצוגה ובחרו **2D Field**. זו מפה שעליה אפשר להציג מיקום של רובוט.
5. בשדה החיפוש של רשימת הנתונים חפשו `Subsystems/Swerve/Pose`. **Pose** היא תנוחה: מיקום וכיוון. פתחו ענפים באמצעות המשולשים שליד שמותיהם אם צריך; ייתכן שהנתון נמצא מתחת לענף `AdvantageKit`.
6. גררו את נתון `Pose` אל אזור **Poses** בתחתית לשונית 2D Field. בחרו סוג **Robot** אם הכלי מבקש לבחור כיצד להציג את הנתון.
7. בחרו מגרש 2026 אם הוא זמין. אם לא, אפשר עדיין לבדוק שינוי במיקום ובכיוון; רק תמונת המגרש תהיה שונה.

**מה אמורים לראות?** סמן של רובוט על המפה ונתון Pose שנבחר ברשימה. הצילום מציג ניסוי אחר, לא את נתוני התבנית שלנו. `FieldSimulation/Fuel` מציג חלקי משחק, ולכן אינו תחליף ל־Pose של הרובוט.

## 6. מפעילים ונוסעים בעדינות

חזרו לחלון הסימולציה. באזור Robot State לחצו **Teleoperated**. בממשק הזה הבחירה מפעילה את מצב הנהיגה. אם משתמשים במקום זאת בתוכנת Driver Station הנפרדת, בוחרים Teleop ואז Enable. אין לחפש בכוח כפתור Enable נפרד בחלון שמופיע בצילום.

| מה עושים בשלט?                         | מה מצפים לראות ב־2D Field?   |
| -------------------------------------- | ---------------------------- |
| מטים מעט את הסטיק השמאלי               | סמן הרובוט משנה מיקום        |
| מחזירים אותו למרכז                     | הרובוט מפסיק לתרגם את מיקומו |
| מטים מעט את הסטיק הימני ימינה או שמאלה | כיוון הסמן משתנה             |
| בוחרים Disabled                        | הטיית השלט אינה מפעילה נהיגה |

זו **תרגום** של הרובוט - שינוי מיקום - לעומת **סיבוב** - שינוי כיוון. בצעו פעולה אחת בכל פעם. קודם בדקו חיווי ציר, ואז שינוי של Pose; כך יודעים באיזה חלק של השרשרת נעצרה התגובה.

## 7. שינוי ראשון: הודעה משלנו

נוסיף הודעה שמופיעה בפלט כשעוברים למצב שליטה בשלט. אין צורך להבין את מערכת הנהיגה: נשנה רק טקסט שרואים על המסך.

1. חזרו ל־Disabled וסגרו את הסימולציה. אם משימת ההרצה עדיין פעילה, עצרו אותה באמצעות פח האשפה של הטרמינל שלה.
2. [פתחו קובץ וחפשו בתוכו](./00-working-in-vscode.mdx#files): הקובץ הוא `src/main/java/frc/robot/Robot.java`, והטקסט לחיפוש הוא `public void teleopInit()`.
3. המתודה הזאת היא קטע קוד שמופעל פעם אחת בכל כניסה למצב Teleop. מיד אחרי הסוגר הפותח `{` שלה הוסיפו את השורה הבאה. השאירו את יתר הקוד במקומו:

```java
System.out.println("Hello from my robot!");
```

`System.out.println` מציגה בפלט את הטקסט שבמירכאות. העתיקו את השורה כולה, כולל המירכאות, הסוגריים והנקודה־פסיק.

4. שמרו את הקובץ ובנו שוב לפי [הוראות הבנייה](./02-template-repository.mdx#first-build). ודאו שמופיע `BUILD SUCCESSFUL`. הפעילו מחדש את הסימולציה והשאירו אותה ב־Disabled.
5. פתחו את [פלט ההרצה ב־VS Code](./00-working-in-vscode.mdx#output), עברו בסימולציה ל־Teleoperated וחפשו `Hello from my robot!`. **תוצאה צפויה:** ההודעה מופיעה פעם אחת בזמן המעבר. אם מצב Teleop נבחר אוטומטית בתחילת ההרצה, ייתכן שהודעה כבר מופיעה; חזרו ל־Disabled כדי לבדוק מעבר נוסף.
6. חזרו ל־Disabled ואז שוב ל־Teleoperated. ההודעה אמורה להופיע פעם נוספת. כך רואים שהשורה שכתבתם רצה בכל כניסה למצב הזה.
7. פתחו Source Control ובדקו שהשינוי שלכם הוא שורת ההודעה ב־`Robot.java`. שמרו Commit ושלחו Push לפי [הצעדים שכבר ביצענו](./02-template-repository.mdx#6-יוצרים-קובץ-אחד-ושומרים-שינוי-ראשון), עם הודעה כמו `Add teleop greeting`.

## בדיקת סיום

הציגו נהיגה ועצירה, ואת ההודעה שלכם בפלט בכל מעבר ל־Teleop. אם תנאי ההרצה לא התקיים, רשמו ״ניסוי חסום״ ואת השגיאה; אל תסמנו הצלחה על סמך חלון פתוח בלבד.
