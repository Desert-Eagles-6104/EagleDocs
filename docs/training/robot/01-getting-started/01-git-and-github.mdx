מה קורה כששני תלמידים משנים את אותו קוד? שליחת תיקיות בשם ״סופי2״ לא מספרת מה השתנה. **Git שומר היסטוריה של שינויים במחשב; GitHub הוא אתר שמארח את ההיסטוריה והקבצים ומאפשר לשתף אותם.**

**מאגר (repository)** הוא פרויקט שקובציו מנוהלים ב־Git. **commit** הוא נקודה שמורה בהיסטוריה: בוחרים שינויים, נותנים להם תיאור ושומרים אותם יחד. **push** שולחת commits שכבר נשמרו מהמחשב למאגר ב־GitHub. אין צורך לזכור את המילים לפני הקריאה; נבצע כל פעולה ונבדוק את התוצאה שלה.

## 1. מתקינים Git ב־Windows

1. פתחו בדפדפן את [דף הורדת Git ל־Windows](https://git-scm.com/downloads/win), ובחרו מתקין המתאים למחשב. במחשב Windows x64 רגיל בוחרים את גרסת x64; אם אינכם בטוחים, שאלו את המנטור.
2. פתחו את הקובץ שהורדתם מתיקיית Downloads. לחצו Next במסכי ההתקנה והשאירו את אפשרויות ברירת המחדל, כולל Git Credential Manager.
3. סיימו באמצעות Finish. סגרו את VS Code ופתחו שוב את **WPILib VS Code 2026**, כדי שיזהה את התוכנה החדשה.

Git Credential Manager הוא הכלי שמאפשר להתחבר ל־GitHub דרך הדפדפן כאשר נשלח שינויים. לא צריך להגדיר אותו בנפרד בתרגיל.

## 2. בודקים שההתקנה הצליחה

פתחו **Terminal → New Terminal**, לחצו אחרי הסמן בחלונית התחתונה, הקלידו את השורה הבאה ולחצו Enter:

```bash
git --version
```

**תוצאה צפויה:** שורה שמתחילה ב־`git version` ומסתיימת במספר גרסה. המספר המדויק אינו חשוב. אם מופיע `not recognized`, פתחו את העורך מחדש ובדקו שוב. אם השגיאה נשארה, הראו למנטור את ההודעה. [כך נראים הטרמינל ומקום ההקלדה](./00-working-in-vscode.mdx#2-פותחים-טרמינל-וכותבים-פקודה).

## 3. יוצרים חשבון ומגדירים שם ל־commits

פתחו [GitHub](https://github.com/signup), מלאו את תהליך יצירת החשבון ואמתו את הדוא״ל באמצעות ההודעה שקיבלתם. בסיום תוכלו להיכנס לאתר ולראות את סמל החשבון בפינה העליונה.

Git צריך לדעת איזה שם וכתובת דוא״ל לרשום ליד השינויים שלכם. בטרמינל כתבו **כל פקודה בנפרד**, החליפו את התוכן במירכאות בפרטים שלכם ולחצו Enter אחרי כל שורה:

```bash
git config --global user.name "Your Name"
git config --global user.email "your-address@example.com"
```

אם אין הודעה אחרי Enter והסמן חזר לשורה חדשה, זה תקין. כדי לראות שהמידע נשמר, הקלידו:

```bash
git config --global user.name
git config --global user.email
```

**תוצאה צפויה:** השם שלכם בשורה הראשונה והכתובת בשנייה. אל תשאירו את `Your Name` או את כתובת הדוגמה. `--global` אומר שההגדרה תשמש גם בפרויקטים אחרים במחשב הזה; במחשב משותף בדקו עם המנטור מה להגדיר.

אפשר לקבל כתובת `noreply` פרטית מתוך הגדרות הדוא״ל של GitHub. השם והדוא״ל מגדירים מי חתום על commit; הם **לא סיסמה ולא כניסה לחשבון**. כאשר בהמשך תופיע בקשת התחברות, השלימו אותה בדפדפן. אין לשמור סיסמאות בקובצי הפרויקט.

## 4. לומדים לקרוא את סדר הפעולות

| מה עושים?                     | מה נשמר או משתנה?     | איך יודעים?                            |
| ----------------------------- | --------------------- | -------------------------------------- |
| Save — שמירה באמצעות Ctrl + S | קובץ במחשב            | הנקודה ליד שם הלשונית נעלמת            |
| Stage — בחירת שינוי ל־commit  | רשימת השינויים שבחרתם | הקובץ עובר ל־Staged Changes            |
| Commit — נקודה בהיסטוריה      | גרסה מקומית עם הודעה  | השינוי נעלם מרשימת השינויים הממתינים   |
| Push — שליחה ל־GitHub         | העותק המרוחק באתר     | ה־commit והקובץ מופיעים אחרי רענון הדף |

**Source Control** הוא החלון שבו VS Code מציגה את השינויים. **diff** הוא השוואה שמראה בדיוק אילו שורות נוספו או הוסרו. בשיעור הבא נעבור על Stage, Commit ו־Push בלחיצות מסודרות, עם קובץ אחד קטן.

### תרגיל: מה לא נכון פה?

תלמיד לחץ Save, סגר את המחשב ואמר ״כולם כבר רואים את השינוי ב־GitHub״. איזה מידע חסר? מה תבדקו?

## בדיקת סיום

הסבירו לחבר איך ניתן לעבוד ללא אינטרנט ומה צריך לעשות כדי שישתף את השינוי אחר כך. בשיעור הבא ניצור את המאגר שבו נשמור את כל הניסויים.
