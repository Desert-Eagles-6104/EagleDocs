נרצה פרויקט אישי שמתחיל מהקוד של הקבוצה. **תבנית היא פרויקט מוכן שמעתיקים למאגר חדש משלנו.** **Clone — שכפול** — מורידה למחשב את הקבצים והיסטוריית Git של המאגר שכבר יצרנו באתר. אלה שני צעדים נפרדים: קודם יוצרים מאגר אישי ב־GitHub, ואז משכפלים אותו למחשב.

## 1. מוצאים את התבנית

1. היכנסו לחשבון שלכם ב־GitHub, ואז פתחו [robot-template של הקבוצה](https://github.com/Desert-Eagles-6104/robot-template).
2. בראש הדף ודאו שהשם הוא `Desert-Eagles-6104 / robot-template`. באזור שמעל רשימת הקבצים ודאו שנבחר `main`: זה שם הענף שממנו מתחילים. **ענף** הוא מסלול עבודה ב־Git; כרגע מספיק לבחור את המסלול שהקבוצה ביקשה.
3. לחצו **Use this template**, ואז **Create a new repository**.

אפשר ללחוץ על צילום המסך כדי לפתוח אותו בגודל מלא בלשונית חדשה. זה שימושי במיוחד כשקוראים בטלפון.

זה צילום לדוגמה מתוך התיעוד הרשמי של GitHub, לא צילום של המאגר האישי שלכם. מחפשים את אותו כפתור בדף התבנית של הקבוצה; מיקומו יכול להשתנות מעט. אם אין Use this template, הראו למנטור את הדף לפני שממשיכים.

## 2. ממלאים את טופס יצירת המאגר

1. בשדה **Owner** — מי הבעלים — בחרו את החשבון שלכם, ולא את חשבון הקבוצה.
2. בשדה **Repository name** כתבו `robot-training` או שם שהמנטור ביקש.
3. בחרו Public או Private לפי הנחיית המנטור. Public פתוח לצפייה; Private דורש הרשאה. אין להוסיף מידע אישי לקוד.
4. לחצו **Create repository** והמתינו.

**תוצאה צפויה:** בראש הדף החדש מופיע `שם-החשבון-שלכם / robot-training`, ורשימת הקבצים כוללת `src` ו־`build.gradle`. אם עדיין כתוב Desert-Eagles-6104, אתם עדיין בדף התבנית; אל תתחילו משם Clone.

## 3. מעתיקים את כתובת המאגר האישי

בדף החדש לחצו על הכפתור **Code**, בחרו **HTTPS** ולחצו על סמל ההעתקה ליד הכתובת. היא אמורה להיראות כך:

```text
https://github.com/YOUR-ACCOUNT/robot-training.git
```

`YOUR-ACCOUNT` כאן הוא מקום לשם המשתמש **שלכם**; הכתובת שמעתיקים מהאתר כבר כוללת אותו. אין להקליד את הדוגמה הזאת כפי שהיא.

## 4. משכפלים ופותחים ב־VS Code

1. פתחו **WPILib VS Code 2026**.
2. לחצו **View → Command Palette** או `Ctrl + Shift + P`. הקלידו `Git: Clone` ובחרו את הפעולה ברשימה.
3. הדביקו את הכתובת שהעתקתם ולחצו Enter.
4. בחלון בחירת התיקייה בחרו היכן לשמור את הפרויקט, למשל Documents. VS Code תיצור שם תיקייה עבור המאגר; אין צורך ליצור קובצי Java ידנית.
5. המתינו להודעת סיום ולחצו **Open**. אם מופיעה שאלת אמון בקוד, אשרו רק כאשר זו התבנית שבחרתם ובדקתם. אם מופיעה כניסה ל־GitHub, השלימו בדפדפן.
6. פתחו **View → Explorer**. זהו אזור רשימת הקבצים בצד העורך.

**תוצאה צפויה:** בפרויקט שלכם רואים את הפריטים הבאים ברמה העליונה:

```text
robot-training
├── build.gradle
├── gradlew
├── gradlew.bat
├── src
└── vendordeps
```

זו רשימת זיהוי, לא צילום מסך ולא הוראה ליצור תיקיות חסרות. **שורש הפרויקט** הוא התיקייה שמכילה את כל הפריטים האלה. אם פתחתם רק את `src`, בחרו **File → Open Folder** ופתחו את תיקיית `robot-training` שמעליה.

## 5. בודקים לאן יישלחו שינויים

פתחו **Terminal → New Terminal** כאשר הפרויקט פתוח. שם התיקייה שבשורת הטרמינל צריך להיות `robot-training`. הקלידו שורה אחת ולחצו Enter:

```bash
git remote -v
```

**origin** הוא הכינוי ש־Git נותנת כאן למאגר ב־GitHub. **fetch** מציינת כתובת לקבלת שינויים, ו־**push** כתובת לשליחתם. צפו לשתי שורות עם הכתובת האישית:

```text
origin  https://github.com/YOUR-ACCOUNT/robot-training.git (fetch)
origin  https://github.com/YOUR-ACCOUNT/robot-training.git (push)
```

אם הכתובת שייכת לקבוצה, עצרו לפני Push ובדקו שיצרתם ושכפלתם את המאגר האישי.

## 6. יוצרים קובץ אחד ושומרים שינוי ראשון

1. ב־Explorer לחצו לחיצה ימנית על תיקיית הפרויקט ובחרו **New File**.
2. כתבו `training-notes.md`, לחצו Enter וכתבו בקובץ: ״ניסוי ראשון: אני מצפה לראות את הרובוט זז בסימולציה״. הסיומת `.md` היא קובץ טקסט לתיעוד, לא קוד Java.
3. לחצו `Ctrl + S`.
4. פתחו **View → Source Control** או `Ctrl + Shift + G`. תחת **Changes** אמור להופיע הקובץ. האות `U` פירושה ש־Git עדיין לא עוקבת אחריו.
5. לחצו על שם הקובץ וקראו את ההשוואה. זו ה־diff: שורות חדשות מסומנות בדרך כלל בירוק; שורות שנמחקו באדום.
6. לחצו על `+` **ליד הקובץ הזה**. הוא אמור לעבור ל־**Staged Changes** — השינויים שבחרתם לשמירה בהיסטוריה.
7. בתיבת ההודעה מעל הרשימה כתבו `Add training experiment notes`, ואז לחצו **Commit**. בסיום הקובץ לא אמור להופיע כשינוי ממתין.
8. פתחו את חלון הפקודות ובחרו **Git: Push**. אם נדרשת כניסה, השלימו בדפדפן וחזרו לעורך.
9. רעננו את דף המאגר האישי ב־GitHub. פתחו `training-notes.md` וודאו שהמשפט שכתבתם מופיע. כך מאמתים שהשינוי הגיע לאתר, ולא רק נשמר במחשב.

### בודקים את התוצאה בלי לנחש

| לפני הפעולה                     | אחרי הפעולה                                  |
| ------------------------------- | -------------------------------------------- |
| `training-notes.md` תחת Changes | אחרי `+`: הקובץ תחת Staged Changes           |
| הקובץ תחת Staged Changes        | אחרי Commit: הוא לא ברשימת השינויים הממתינים |
| הקובץ קיים רק במחשב             | אחרי Push ורענון GitHub: הוא מופיע גם באתר   |

בתיבת ההודעה של Source Control כותבים את **תיאור השינוי**. את תוכן הקובץ עצמו כותבים באזור העורך. אפשר להצביע על המעבר ברשימות גם בלי להבין את כל הסמלים של Git.

אם מתקבלת שגיאה, אין צורך ללחוץ שוב ושוב על Commit או Push. קראו את ההודעה והראו אותה למנטור. לא מוסיפים ל־commit קבצים אחרים שלא בדקתם.
