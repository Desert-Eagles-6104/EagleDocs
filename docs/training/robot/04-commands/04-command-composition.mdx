נרצה להפעיל גלגל לזמן קצר, להמתין ולעשות זאת שוב. אין צורך ב־sleep או בלולאה חוסמת: נרכיב פקודות שמחזירות שליטה למתזמן בכל מחזור.

**הרכבת פקודות** פירושה לקחת פעולות קטנות ולחבר אותן לפעולה גדולה. **רצף (sequence)** עושה אחת אחרי השנייה. **מקביל (parallel)** מתחיל פעולות יחד. **המתנה** בפקודה משאירה את המתזמן פנוי לבדוק כפתורים ומצבים; אין צורך לחסום את התוכנית בלולאה.

`withTimeout(1.0)` אומרת ״הפעילו את הפקודה לכל היותר שנייה״. `Commands.waitSeconds(0.5)` היא פקודה שממתינה חצי שנייה בלי לבקש פלט מנוע.

## 1. רצף עם פקודות קיימות

ב־`RobotContainer` הוסיפו import:

```java
import edu.wpi.first.wpilibj2.command.Commands;
```

בתוך `configureTeleopBindings()`, באותה `trainingFlywheel.ifPresent`, הוסיפו:

```java
this.driverController.eastButton().onTrue(Commands.sequence(
    new MotorSubsystemSetPercentage<>(flywheel, () -> 0.15).withTimeout(1.0),
    Commands.waitSeconds(0.5),
    new MotorSubsystemSetPercentage<>(flywheel, () -> 0.20).withTimeout(1.0)
));
```

`withTimeout` מסיימת את המקטע אחרי הזמן. `end` של פקודת המנוע מבטלת את הפלט, לכן ההמתנה אינה משאירה בקשת הפעלה. הגלגל עדיין עשוי לדעוך בזמן ההמתנה.

`sequence` עוברת לפקודה הבאה רק אחרי שהקודמת הסתיימה. הקבוצה מחזיקה את איחוד הדרישות של ילדיה, גם בזמן ההמתנה. `parallel` מתחילה פעולות יחד ומסתיימת אחרי שכולן הסתיימו. אי אפשר לשים במקביל שתי פקודות שדורשות את אותו flywheel. גם `race` או `deadline` אינן דרך לעקוף קונפליקט דרישות.

אל תצרפו את אותו מופע פקודה לשתי קבוצות. צרו מופעים חדשים או factory שמחזירה פקודה חדשה, כפי שהתבנית עושה עבור אוטונומי.

### לפני תוספת אוטונומית, צופים ברצף מהכפתור

East הוא Circle ב־PS5 או B ב־Xbox. הוסיפו את החיבור בתוך גוף `trainingFlywheel.ifPresent`, שמרו, בנו והריצו. לחצו פעם אחת ושחררו; כאן משתמשים ב־onTrue, ולכן הרצף ממשיך עד סיומו.

| זמן מתחילת הרצף       | בקשה צפויה | מה מצפים לראות?                      |
| --------------------- | ---------- | ------------------------------------ |
| 0 עד בערך 1 שנייה     | 0.15       | מהירות עולה                          |
| בערך 1 עד 1.5 שניות   | פלט מבוטל  | הגלגל יכול להאט בגלל Coast           |
| בערך 1.5 עד 2.5 שניות | 0.20       | מהירות עולה שוב                      |
| אחרי הסיום            | פלט מבוטל  | שם הפקודה חוזר ל־None והמהירות דועכת |

אם המהירות ממשיכה לקבל פלט בשלב ההמתנה, בדקו שיש `withTimeout` ושהפקודה מסיימת דרך `end`. רק אחרי שניסוי הכפתור עובד מצרפים את אותה התנהגות לאוטונומי.

## 2. מצרפים למסלול האוטונומי הקיים

### קוראים את בחירת האוטונומי

פתחו `src/main/java/frc/robot/autos/AutoProfiles.java` עם Ctrl + P. חפשו `createAutosMap` בתוך הקובץ. **Map** היא אוסף של זוגות: שם אפשרות והתיאור שלה. `map.put` מוסיפה זוג. **AutoProfile** היא מחלקת נתונים קצרה, שנכתבה כאן כ־record; הבנאי שלה מקבל דרך ליצור פקודה ותנוחת התחלה. לא צריך לכתוב Map או record חדשים.

`Supplier<Command>` נותנת דרך לקבל פקודה חדשה כאשר בוחרים את האוטונומי. לכן החלק `() -> { ... }` ייצור אותה בעת בקשה, ולא בזמן שכל התפריט נבנה. `var` מבקשת מ־Java להסיק את טיפוס המשתנה מהערך שהוצב בו. `orElseThrow()` מקבלת את האובייקט מה־Optional, או זורקת חריגה אם הוא חסר; כאן משתמשים בה רק במסלול SIM שבו כבר יצרנו את המנגנון.

`AutoProfiles` מחזירה `Map<String, AutoProfile>`. ה־`AutoProfile` מחזיק `Supplier<Command>` ותנוחת התחלה. בתוך `createAutosMap()`, לפני `return map`, הוסיפו תוספת **בסימולציה בלבד**:

```java
if (frc.DELib26.util.RunMode.isSim()) {
    map.put("Training flywheel", new AutoProfile(
        () -> {
            var flywheel = frc.robot.RobotContainer.getInstance()
                .trainingFlywheel.orElseThrow();
            return edu.wpi.first.wpilibj2.command.Commands.sequence(
                new frc.DELib26.subsystems.motorSubsystems.commands.MotorSubsystemSetPercentage<>(
                    flywheel, () -> 0.15).withTimeout(1.0),
                edu.wpi.first.wpilibj2.command.Commands.waitSeconds(0.5),
                new frc.DELib26.subsystems.motorSubsystems.commands.MotorSubsystemSetPercentage<>(
                    flywheel, () -> 0.20).withTimeout(1.0)
            );
        },
        () -> new Pose2d()
    ));
}
```

השמות המלאים כאן מאפשרים להוסיף בלי לנחש imports; אפשר לקצר עם imports ב־VS Code. אין צורך לשנות `Robot.autonomousInit()`: היא כבר מבקשת את הפקודה ומתזמנת אותה. ב־Disabled בחרו `Training flywheel` מתוך `Auto/Auto` בדשבורד, ואז עברו Autonomous ו־Enable. ברירת המחדל `Stay in place` נשארת כפי שהיא.

### מוצאים את אפשרות האוטונומי על המסך

**chooser** היא רשימת בחירה שהתבנית מפרסמת. **Glass** היא תוכנה נוספת של WPILib, שמאפשרת גם לשלוח בחירות לרובוט, לא רק לצפות בגרף. נשתמש בה כדי לבחור איזה אוטונומי יופעל.

1. השאירו את הסימולציה ב־Disabled. ב־VS Code פתחו את חלון הפקודות ובחרו **WPILib: Start Tool**, ואז **Glass** ברשימת הכלים.
2. בחלון Glass מצאו **NetworkTables Settings**. ב־**Mode** בחרו **Client**. בשדה **Team/IP** כתבו `localhost`, ואז לחצו **Apply**. localhost פירושו המחשב שבו התוכנה רצה; כאן זה אותו מחשב שמריץ את הסימולציה.
3. הסתכלו בכותרת החלון: החיבור צריך לעבור למצב מחובר. בחלונית NetworkTables אמורים להופיע ענפי נתונים.

אפשר ללחוץ על צילום המסך כדי לפתוח אותו בגודל מלא בלשונית חדשה. זה שימושי במיוחד כשקוראים בטלפון.
