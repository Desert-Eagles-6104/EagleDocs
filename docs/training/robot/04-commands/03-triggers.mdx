לפעמים רוצים פעולה פעם אחת, לפעמים כל עוד כפתור מוחזק, ולפעמים עד לחיצה נוספת. הבחירה צריכה להתאים להתנהגות שרוצים, לא לשם שנראה קצר יותר.

## 1. בחירה לפי משמעות

| חיבור                   | משמעות                                |
| ----------------------- | ------------------------------------- |
| `onTrue(command)`       | תזמון במעבר false → true              |
| `onFalse(command)`      | תזמון במעבר true → false              |
| `whileTrue(command)`    | תזמון בעלייה, ביטול בירידה            |
| `toggleOnTrue(command)` | החלפה בין תזמון לביטול בכל לחיצה חדשה |

המתזמן קורא את הטריגרים במחזורים שלו. lambda מספרית כמו `() -> 0.15` אינה Trigger; היא מקור לערך של הפקודה.

## 2. ברירת המחדל שכבר נסעתם איתה

ב־`configureTeleopBindings()` מותקנת `TeleopDrive` בתור default command של swerve. כשהתת־מערכת פנויה, המתזמן מתזמן אותה. כשהפקודה הופכת פעילה, `execute()` קוראת את השלט. זו הסיבה שנהיגה עובדת גם כשה־`teleopPeriodic()` ריקה.

אין צורך בפקודת ברירת מחדל לגלגל בשלב הזה: `end` מבטלת את פלטו. default command חייבת לדרוש את תת־המערכת שאליה היא משויכת. לא משתמשים בפקודה שמסתיימת מיד בתור ״לולאת עצירה״ בלי להבין את מחזורי התזמון.

## 3. ניסוי toggle

במאגר האישי החליפו זמנית את North מ־`whileTrue` ל־`toggleOnTrue`. נבאו מה יקרה אחרי לחיצה ושחרור, ואז לחיצה נוספת. בדקו גם Disable וחזרה ל־Teleop. החזירו את `whileTrue` לאחר תיעוד התוצאה, כדי לשמור את התנהגות הפרויקט בהמשך.

### מה לא נכון פה?

תלמיד שם את כל ה־bindings ב־`robotInit()` בלבד. אחרי Disable הם נעלמים. האם צריך לקרוא ל־robotInit שוב?

## בדיקת סיום

בחרו חיבור מתאים לאיפוס תנוחה, להפעלת גלגל בזמן החזקה ולמצב הפעלה שנשמר עד לחיצה נוספת. הסבירו מה יקרה אם הפקודה מסתיימת בעצמה כשהכפתור עדיין לחוץ. נדרש מעבר false → true חדש כדי ש־whileTrue תתזמן שוב.
