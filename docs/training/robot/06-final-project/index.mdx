תתכננו פתרון משלכם ותציגו בדיקות שאחרים יכולים לחזור עליהן.

## לפני שמתחילים

המשיכו באותו מאגר אישי מהשלב הקודם. שמרו את העבודה, בדקו git status, וודאו שאפשר להסביר את הבדיקה האחרונה שביצעתם.

## תיק הניסויים שלכם

שמרו תחזית לפני כל הרצה ותוצאה אחריה. בסוף השלב בחרו שינוי אחד והסבירו: באיזה קובץ שיניתם, מי קורא לו, ומה המדידה שמוכיחה את התוצאה. צרפו commit שמרכז שינוי אחד ברור. אם ניסוי נעצר בגלל תשתית התבנית, רשמו את השגיאה ואת התנאי שחסר, בלי להציג אותו כבדיקה שעברה.
