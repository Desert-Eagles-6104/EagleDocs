כעת תתכננו שינוי שמחבר קלט, פקודות, מדידות ובקרה. **אין פתרון מלא להעתקה: אתם בוחרים את ארגון ההתנהגות ומוכיחים שהוא עומד בדרישות.** ממשיכים באותו גלגל ובאותו מאגר אישי.

## 1. דרישות ההתנהגות

- כפתור אחד מפעיל בקרת מהירות ליעד מתון שנבחר בסימולציה; שחרור מבטל פלט.
- כפתור אחר מפעיל פעולה מתחרה. שתי הפעולות דורשות אותו מנגנון, והתוצאה של לחיצה יחד מתועדת.
- מופיעים יעד, מהירות מדודה, שגיאה ושם פקודה פעילה.
- חיווי ״מוכן״ מופיע רק לאחר עשרה מחזורים רצופים שבהם המהירות בסבילות של 2 RPS סביב יעד פעיל.
- סטייה מחוץ לסבילות מאפסת את מונה היציבות. מצב Disabled או פעולה שבוטלה אינם ״מוכן״, גם אם נשאר יעד שמור.
- מצב אוטונומי לימודי ב־`AutoProfiles` מפעיל בקרת מהירות, בודק הגעה, מבצע פעולה קצרה נוספת ומבטל פלט בסיום.
- המתנה ליעד מוגבלת בזמן: אם לא הגיעו בתוך 3 שניות, מדווחים כישלון ואין ממשיכים כאילו המנגנון מוכן.
- יציאה מ־Teleop, Disable וביטול באמצע רצף משאירים בקשת פלט מבוטלת.

עשרה מחזורי מתזמן הם בדרך כלל כ־200 ms. אם צריך זמן מדויק, מודדים זמן; לא מחשבים ממנו דרישת בטיחות לחומרה.

## 2. מתכננים לפני מימוש

כתבו מי מחזיק את מונה היציבות, מי מאפס אותו ואיך הפקודה יודעת אם הצליחה או הגיעה ל־timeout. תכננו מה `initialize`, `execute`, `isFinished` ו־`end` יעשו. אפשר להוסיף מחלקת פקודה חדשה בשלב הזה; השתמשו ב־`MotorSubsystemTalon` ובפעולות שכבר בדקנו.

שימו לב: הרכבה עם `withTimeout` לבדה אינה מסמנת הצלחה. גם פקודה שהסתיימה בגלל timeout יכולה להעביר רצף לשלב הבא. צריך תנאי או מצב תוצאה כדי לבחור אם להמשיך.

## 3. טבלת קבלה

| בדיקה                         | תוצאה נדרשת                  | ראיה              |
| ----------------------------- | ---------------------------- | ----------------- |
| לחיצה ושחרור                  | פקודה פעילה ואז ביטול פלט    | גרף ושם פקודה     |
| שתי לחיצות חופפות             | בעל שליטה יחיד               | סדר אירועים מתועד |
| יעד אפשרי                     | חיווי רק אחרי רצף יציב       | יעד, מדידה ומונה  |
| יעד בלתי ניתן להשגה בסימולציה | timeout וכישלון מדווח        | זמן ותוצאה        |
| Disable באמצע כל שלב          | בקשת פלט מבוטלת              | מתח ומצב          |
| חזרה ל־Teleop                 | bindings תקינים ללא כפילויות | ניסוי חוזר        |

חזרו ליעד המתון אחרי ניסוי ה־timeout. אין חובה להוסיף מסלול swerve, ירי כדורים או זיהוי אובייקטים. הרחבה אפשרית היא הודעת מצב לפי נתון הראייה הקיים, עם בדיקת תוקף מתועדת.

## 4. מה מגישים?

ענף אישי עם commits קטנים, הסבר של זרימת הקריאות, טבלת בדיקות ולוג או צילום גרף אמיתי. סמנו במפורש בדיקות שלא רצתם. מנטור או תלמיד אחר צריכים להיות מסוגלים לחזור על הניסוי בלי שתעמדו לידם.
